# PB-04-06 Hunt Replay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expor a tradução validada de `HuntDefinition` para `KernelScenario` v3 e preparar a
prova golden da primeira hunt sem fabricar a região ausente do snapshot.

**Architecture:** `@huntbound/content` valida e traduz conteúdo Tibia-aware na fronteira do kernel.
O cenário contém apenas geometria, blueprints e posições; IDs de palette, região e criaturas ficam
na `HuntDefinition`. A sessão real passa por `tools/replay` e só será congelada quando o artefato
`hunt.json` produzido por PB-04-04 estiver presente.

**Tech Stack:** TypeScript strict, contratos Zod em `@huntbound/contracts`, Vitest, pnpm workspace,
`tools/replay` existente e JSON canônico.

## Global Constraints

- `buildHuntScenario` mora em `@huntbound/content`; `@huntbound/simulation` não ganha dependência.
- A tradução é total: `collision → blockedTiles`, `transitions.entries → transitions`,
  `spawns.groups → spawnGroups`, blueprints e `playerStart` da `HuntDefinition`.
- `scenarioId` é `scenario:${huntId}` e `scenarioRevision` é `huntRevision`.
- O seed não entra em `KernelScenario`; ele permanece no command-log/snapshot do replay.
- Nenhuma chave ou valor de conteúdo (`palette`, `serverId`, `clientId`, `creatureKey`, `regionId`)
  atravessa para o cenário.
- O jogador é o único ator inicial e recebe facing `s`.
- Nenhuma dependência externa nova entra no workspace.
- Nenhum arquivo em `packages/simulation`, `packages/contracts`, `packages/assets` ou `apps/game`
  será alterado.
- A região real da hunt não está no checkout atual; o golden real, seus hashes e `hunt:check` não
  podem ser gerados usando uma geometria sintética.

- [ ] **Step 3: Implement the smallest projection that satisfies the tests.**

Use the following pure mapping; do not inspect `palette`, `regionId` or `creatureKey` while building
the output:

```ts
const scenario = {
  schemaVersion: SIMULATION_SCHEMA_VERSION,
  scenarioId: `scenario:${hunt.huntId}`,
  scenarioRevision: hunt.huntRevision,
  width: hunt.region.width,
  height: hunt.region.height,
  floors: hunt.region.floors.map((floor) => ({
    z: floor.z,
    blockedTiles: floor.collision.map((i) => [i % hunt.region.width, Math.floor(i / hunt.region.width)] as const),
  })),
  transitions: hunt.transitions.entries.map(({ from, to }) => ({ from, to })),
  spawnGroups: hunt.spawns.groups.map((group) => ({
    center: group.center,
    radius: group.radius,
    slots: group.slots.map((slot) => ({
      blueprintId: slot.blueprintId,
      position: {
        x: group.center.x + slot.offsetX,
        y: group.center.y + slot.offsetY,
        z: group.center.z + slot.offsetZ,
      },
      respawnTicks: slot.respawnTicks,
    })),
  })),
  maxLiveActors: hunt.spawns.maxLiveActors,
  blueprints: hunt.blueprints.map((blueprint) => ({ ...blueprint })),
  initialActors: [{ blueprintId: hunt.playerBlueprintId, position: hunt.playerStart, facing: 's' }],
};
```

Call `validateHuntDefinition` before the mapping and `validateKernelScenario` after it. The seed
parameter is intentionally unused in the projection; use `void seed` to make that boundary
explicit. The loader calls `validateHuntDefinition(raw)` and returns its result unchanged.
