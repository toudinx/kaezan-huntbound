# PB-04-08 Hunt Scene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Present the frozen Venore Rotworm Cave in Phaser and translate keyboard/touch input into one deterministic kernel command per available tick.

**Architecture:** Keep input, camera, interpolation, tile-layer projection, and event-to-view state as pure or DOM-testable modules. `HuntScene` owns only Phaser objects and delegates simulation work to a supplied kernel driver; `SceneBridge` carries shell snapshots and simulation events without exposing kernel state. The bootstrap loads the PB-04 pack through its stable catalog route, builds the existing hunt scenario, and composes the scene beside the existing shell/probe.

**Tech Stack:** TypeScript 7 strict, Phaser 4.2.1, Vite 8, Vitest 4, existing `@huntbound/contracts`, `@huntbound/content`, `@huntbound/simulation`, and `@huntbound/assets` APIs.

## Global Constraints

- No new dependencies.
- Do not modify `packages/**` or `tools/**`; changes stay in `apps/game/**`, `package.json` staging scripts, and the PB-04 state handoff.
- `apps/game` contains presentation only: no collision, cooldown, spawn, transition, terrain, or random rules.
- The scene resolves assets only through stable keys and resolved asset descriptors; no media path literal enters `apps/game/src`.
- Tile draw order is `ground` → `objectsBelow` → actors → `objectsAbove`; only the active floor is mounted.
- `InputMap.drain()` returns and clears actions, and a held direction contributes at most one action per drain.
- Camera scrolling is clamped to the supplied world bounds; interpolation clamps alpha to `[0, 1]`.
- `actor/move-blocked` never changes a presentation target or starts interpolation.
- Existing PB-03 kernel probe and asset-pack browser contract remain green.
